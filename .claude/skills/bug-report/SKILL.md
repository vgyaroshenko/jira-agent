Створення баг-репорту. Деталі бага: $ARGUMENTS (або з контексту розмови).

Виконуй суворо по кроках.

## Крок 1 — QA-оцінка

Дай коротку оцінку (2-3 речення) як досвідчений QA-інженер:
- Це баг чи очікувана поведінка? Аргументуй.
- Якщо баг — фронт (UI, рендеринг, JS-логіка) чи бек (API, бізнес-логіка)?

## Крок 2 — Уточнення (якщо потрібно)

Якщо критично не вистачає інформації — задай **одне** уточнювальне питання. Якщо достатньо — пропусти цей крок.

**Не питай** про кроки відтворення та очікуваний результат — виведи їх сам.

## Крок 3 — Середовище і браузер

Використай `AskUserQuestion` з двома питаннями в одному виклику:
- "На якому середовищі знайдено баг?" → DEV, Stage, Prod
- "У якому браузері?" → Edge, Chrome, Safari, Firefox

**Примітка:** Edge — перший варіант (пріоритет для цього користувача).

## Крок 4 — Розділ, сторінка, мова

Використай `AskUserQuestion` з трьома питаннями в одному виклику:
- "Розділ сайту?" → Сторінка продукту, Кошик, Оформлення замовлення, Авторизація / Реєстрація
- "Сторінка (URL або назва)?" → Не вказано, Головна, Сторінка категорії, Сторінка пошуку
- "На якій мові створити баг-репорт?" → UA — українська, RU — русский, EN — English

**Не генеруй баг-репорт до отримання відповідей на обидва кроки.**

## Крок 5 — Згенеруй та опублікуй

Визнач ключ проекту (з контексту або запитай). Згенеруй баг у форматі:

```
##ENV##
Середовище: ...
Браузер: ...
Розділ: ...
Сторінка: ...

##DESC##
Опис проблеми (2-4 речення).

##STEPS##
1. Крок
2. Крок

##EXPECTED##
- Очікувана поведінка

##ACTUAL##
- Фактична поведінка

##ADDITIONAL##
Додаткова інформація або Не вказано
```

Опублікуй:
```bash
python main.py new-bug --title "Короткий заголовок до 80 символів" --lang UA --project GN << 'EOF'
##ENV##
...
EOF
```

Прапор `--related GN-123` — якщо баг пов'язаний з конкретною задачею.
