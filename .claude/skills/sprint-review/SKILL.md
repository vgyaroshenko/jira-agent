Огляд спринту для проекту $ARGUMENTS.

## Крок 1 — Отримай задачі спринту

```bash
python main.py sprint $ARGUMENTS
```

## Крок 2 — Розбий задачі на групи

Із виводу команди визнач:
- Задачі з `❌TC` — потребують тест-кейсів
- Задачі з `❌QC` — потребують перевірки якості
- Задачі з обома `✅TC ✅QC` — вже готові

Виведи зведену таблицю користувачу.

## Крок 3 — Обробка задач без тест-кейсів (❌TC)

Для кожної задачі з `❌TC`:

1. Отримай дані: `python main.py fetch ISSUE-KEY`
2. Перевір якість (як у `/qa-check`):
   - Якщо задача неякісна → залиш коментар репортеру і **пропусти генерацію тест-кейсів** для неї
   - Якщо задача якісна → генеруй тест-кейси

3. При генерації тест-кейсів — визнач мову (`python main.py lang $ARGUMENTS`), потім генеруй у **табличному форматі** і публікуй коментарем:
   ```bash
   python main.py comment ISSUE-KEY << 'EOF'
   | Case | Description | Steps | Priority |
   |---|---|---|---|
   | TC-001 — ... | ... | ... | High |
   EOF
   ```

## Крок 4 — Підсумок

Після обробки всіх задач — виведи підсумок:
- Скільки задач оброблено
- Для скількох згенеровано тест-кейси
- Для скількох залишено коментар якості
- Які пропущені і чому
