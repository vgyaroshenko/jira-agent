# Jira QA Agent

AI-помічник для QA-інженера. Працює через Claude Code — без окремого API-ключа Anthropic.

## Налаштування

```bash
cd /Users/volod/dev/claude/jira-agent
source .venv/bin/activate
```

Налаштування Jira — у файлі `.env`. Мова проекту — `PROJECT_LANG_KEY` у `.env`.

---

## Скіли (slash commands)

Скіли — у `.claude/skills/<name>/SKILL.md`. Викликати: `/назва аргументи`.

| Скіл | Що робить |
|---|---|
| `/test-cases GN-1808` | QA-аналіз функціональності → сьюти → тест-кейси (позитивні, негативні, граничні) |
| `/bug-report` | Створення баг-репорту з описом у вільній формі |
| `/new-task` | Створення Story / Task / Improvement |
| `/qa-check GN-1808` | Перевірка якості задачі |
| `/sprint-review GN` | Огляд спринту + тест-кейси для задач без TC |
| `/daily-report` | Тезисний звіт за день по проекту — тригериться і фразою на кшталт "все на сьогодні" |

## CLI команди

| Команда | Що робить |
|---|---|
| `python main.py fetch GN-1808` | Отримати дані задачі (+ вкладення в /tmp/jira-ISSUEKEY/) |
| `python main.py comment GN-1808 [--mention ID]` | Додати коментар (текст зі stdin) |
| `python main.py update GN-1808 [--title "..."] [--lang UA]` | Оновити заголовок та/або опис (опис зі stdin) |
| `python main.py new-bug --title "..." --lang UA --project GN [--related GN-123]` | Створити баг (опис зі stdin) |
| `python main.py new-task --title "..." --lang UA --type Story --project GN` | Створити задачу (опис зі stdin) |
| `python main.py publish-tests GN-1808 [--convert]` | Опублікувати тест-кейси коментарем; `--convert` конвертує людиночитаємий формат у таблицю |
| `python main.py attach GN-1808 /path/to/file` | Прикріпити файл до задачі |
| `python main.py lang GN` | Повернути мову проекту з .env |
| `python main.py sprint GN` | Вивести задачі активного спринту |

**Критично:** завжди передавай `--lang` і `--project` (або `--type`) явно — інакше команда запустить інтерактивний вибір у терміналі і зависне.

## Формати

### Визначення мови

Пріоритет: `python main.py lang PROJECT_KEY` → якщо є, використовуй. Інакше — за заголовком задачі: і/ї/є/ґ → UA, ё/ы/ъ/э → RU, інше → EN.

### Формати тест-кейсів

**Варіант 1 — markdown-таблиця** (для коментаря в Jira → Google Sheets):

`\n` у Steps — буквальні символи `\` і `n`, код конвертує при відправці. Якщо є сьюти — 5 колонок, інакше 4:

```
| Suite | Case | Description | Steps | Priority |
|---|---|---|---|---|
| S1 — Назва | TC-001 — Назва | Передумови | 1. Крок\n2. Крок\nОР: результат | High |
```

Для Google Sheets: відкрий коментар в браузері → виділи таблицю → скопіюй → вставити в Sheets.

**Варіант 2 — людиночитаємий** (для файлу `test-cases/ISSUE_KEY.md`, для читання та зберігання):

```
## S1 — Назва сьюту

### TC-001 — Назва
Опис: Передумови
Пріоритет: High

Кроки:
1. Крок
ОР: результат
```

Priority: `High` — критичний функціонал, `Medium` — основні сценарії, `Low` — граничні та негативні.

### Шаблон задачі (##...## маркери)

```
##DESC##
Вступний опис — що потрібно реалізувати і яку бізнес-проблему вирішує. 1-2 речення.

##SECTION## 1. Назва вимоги
- Умова або контекст
- Конкретна поведінка
- Якщо є текст для відображення або приклад — окремий буллет

##AC##
AC1. Назва сценарію\nУмова: що активне або що відбувається.\n✅ Очікуваний результат: конкретний результат.
AC2. ...
```

Для Improvement — додай секції "Поточна поведінка", "Очікувана поведінка", "Цінність для користувача" замість SECTION з вимогами.

### Шаблон баг-репорту (##...## маркери)

```
##ENV##
Середовище: PROD / STAGING / DEV / Не вказано
Браузер: значення або Не вказано
Розділ: значення або Не вказано
Сторінка: значення або Не вказано

##DESC##
Розгорнутий опис проблеми — 2-4 речення.

##STEPS##
1. Крок перший
2. Крок другий

##EXPECTED##
- Очікувана поведінка

##ACTUAL##
- Фактична поведінка

##ADDITIONAL##
Додаткова інформація або Не вказано
```

## Загальні правила

- **Не додавай** "🤖 Автоматично згенеровані..." та будь-які авто-позначки в коментарі Jira
- **Перевіряй покриття** після генерації тест-кейсів: кожен пункт опису і кожен AC → мінімум один тест-кейс. "(опционально)" і налаштування вкл/викл — завжди окремі кейси
- **Edge і браузер:** у питаннях про браузер — Edge перший варіант
- **Вкладення:** якщо задача має вкладення — прочитай їх усі перед генерацією тест-кейсів
